Build and run

npm ci
npm run build
npm run serve

Open http://127.0.0.1:8080. After building, standalone.html is a self-contained demo. All demonstration measurements are synthetic. The library does not poll services or download fonts.

Publication targets are npm bamtigraph, JSR @safe/bantigraph, and Go github.com/gosuda/BamtiGraph. Building and dry runs do not publish packages.

TypeScript and browser integration

import { traffic, daily } from 'bamtigraph';
const chart = traffic([0, 300, 600], [180e6, 195e6, 188e6], [42e6, 45e6, 43e6], {
  title: 'Traffic - uplink',
  timeAxis: daily('UTC'),
  fonts: { mode: 'bitmap' },
  watermark: ''
});
const bytes = chart.render().toPNG();

For an ordinary HTML page, load dist/bamtigraph.global.js and use BamtiGraph.traffic. The npm package exposes ESM and CommonJS with matching declarations; JSR exports strict TypeScript source.

Attach the canvas to the document before chart.mount(canvas). A controller supports update and destroy. Destroy on component teardown. Pointer and keyboard inspection uses an overlay, never the export pixels. Use bitmap mode in DOM-free Node/Deno.

Native Go

go run ./examples/quickstart -o examples/output/quickstart.png
go run ./cmd/bamtigraph -input examples/traffic.csv -o traffic.png
go run ./cmd/bamtigraph -demo -watermark BAMTIGRAPH -o branded.png

Start with Traffic or NewGraph, set TimeAxis, YAxis, and Watermark, then call Save. Parent directories must exist. Use Epoch(time.Time) for Unix seconds. Graph configuration is mutable: do not mutate it during concurrent rendering.

Go requires an installed TrueType-outline TTF/TTC font. Set FontConfig{Mono: path, Strict: true} or use CLI -font. Fonts are not bundled or fetched. The native unhinted font rasterizer differs from browser system text; complex shaping, CFF/WOFF, and automatic glyph fallback are not supported.

White-label text

The default watermark is empty in both languages. TypeScript watermark and Go Graph.Watermark place custom text in the right-hand vertical margin. Use BAMTIGRAPH only when you want explicit library branding. Clearing the value removes it. The demo's Custom edge text field exposes this control.

Edit assets/brand.js for surrounding UI labels and assets/ui.css for page colors. Graph theme, layout, series colors, and watermark size/color are separate options. A mark that cannot fit produces an error instead of overwriting the plot. Browser system mode and an appropriate installed native Go font support Unicode input.

Pixel verification

The two-series reference geometry is 595 × 211, with plot anchors (64,34) → (564,156). Integer scale replicates pixels rather than resampling them.

The original-vs-port checks compare 13 fixtures at two scales and two watermark states in each language: 104 whole-image RGBA comparisons with zero differing channels. Browser integration checks also verify native PNG decoding, golden bitmap pixels, exact scaling, and controller lifecycle. Native and TypeScript fonts are not claimed to match one another or an unrelated screenshot.

Release setup

Pushing a stable version tag such as v1.0.0 publishes npm bamtigraph and JSR @safe/bantigraph through separate OIDC workflows. No GitHub Release needs to be created. Prerelease tags containing a hyphen are skipped.

npm

In the npm package Settings, add a GitHub Actions Trusted Publisher with these exact values:

  • Organization/User: gosuda
  • Repository: BamtiGraph
  • Workflow filename: publish-npm.yml
  • Environment: npm

Permit direct npm publish in Allowed actions. Create the matching GitHub environment npm and add approval rules if desired. The workflow installs an OIDC-capable npm 11 CLI on Node 24 and requires no long-lived npm token. Existing immutable npm versions, including the initial 0.1.0 bootstrap release, are skipped; changed code needs a new version. See npm's trusted publishing guide.

JSR

  1. Obtain publishing access to the JSR @safe scope and create or select bantigraph.
  2. In package Settings, link gosuda/BamtiGraph.
  3. Create the GitHub environment jsr and add approval rules if desired.

The JSR workflow is publish-jsr.yml. See JSR's publishing guide.

Include the workflows in the tagged commit, align package.json, jsr.json, and source VERSION, then push the matching v<version> tag. Verification runs before publication. Publisher jobs use contents: read and id-token: write; registry permissions and repository linkage must be configured outside this repository.

Development and image comparisons

npm run verify
go test -race ./...
go run ./examples/parity -out examples/output
go run ./examples/compare -reference before.png -actual after.png -diff difference.png

Comparison inputs are your own images. Only selected README screenshots in docs/images/ are committed; generated binaries and temporary outputs are excluded. The parity example renders the JSON fixtures without claiming a pixel comparison. Supply -reference-dir /path/to/references to compare against external python_<case>.png images. Regression baselines retain full RGBA SHA-256 digests in testdata/golden.json and testdata/go_golden.json, with font fingerprints where applicable. go run ./tools/updategolden -update explicitly replaces the native text baseline; review intentional rendering changes before accepting a new digest.
